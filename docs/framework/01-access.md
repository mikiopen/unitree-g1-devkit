# 设备接入

设备接入 → 感知 → 决策 → 执行 → 反馈 → 部署维护

## 能力目标

识别厂商开放的硬件、固件和接口，建立应用与设备之间的连接。覆盖硬件认知、Linux/Python/C++环境、依赖与构建、SDK、DDS/ROS 2、网络，以及按需使用的串口、CAN和USB外设。

本环节负责连接和能力声明；控制权限、型号与支持范围来自实际设备资料。

### 接入能力清单

| 子方向 | 先回答的问题 | 最小成果 |
| --- | --- | --- |
| 设备认知 | 型号、计算单元、外设和开放权限是什么？ | 设备能力表 |
| 软件环境 | 哪个程序在哪台机器、哪个解释器上运行？ | 环境与依赖清单 |
| 网络与SDK | 通过哪个接口通信，如何识别目标？ | 连接与请求记录 |
| 外设适配 | 供电、接口、驱动、设备路径与数据格式是否匹配？ | 外设接入说明 |
| 时间与配置 | 谁产生时间，配置如何区分环境？ | 时钟与配置约定 |

## 前置条件

电脑起步只需Python3.10+；设备接入另需型号、自由度、固件、SDK、网卡与开放权限。[设备基线模板](../../configs/device-baseline.example.json)用于记录这些条件。ROS 2、CAN等按接口选用，不要求全部安装。

## 输入输出与接口

| 边界 | 约定 |
| --- | --- |
| 输入 | 设备标识、连接参数、依赖与能力声明 |
| 输出 | 环境检查结果、连接状态、可读状态与可调用能力清单 |
| 错误 | 缺依赖、连接失败、不支持的接口和权限不足应明确区分 |

扩展时将厂商SDK放在设备适配模块后面，保留设备ID、单位、数据来源、超时和错误语义。这是接口设计要求；本仓库尚未实现通用设备适配API。

## 最小示例

1. 从[00系统地图](../tutorials/00-overview.md)明确运行位置，再做[01环境检查](../tutorials/01-environment.md)。
2. 在仓库根目录运行：

   ```text
   python tools/check_environment.py --profile pc
   python g1.py doctor
   ```

3. 用[06回环UDP](../tutorials/06-udp.md)理解请求与回复。它只接本机模拟端。
4. 有设备后按[02网络](../tutorials/02-network.md)接入，并先完成[03只读状态](../tutorials/03-state.md)。

## 可修改与扩展点

可替换设备SDK、增加相机或手部外设、加入ROS 2节点、调整部署机器与连接方式。每增加一种适配，补充能力清单、输入输出和连接失败行为。

驱动编写、MCU/RTOS、BSP与硬件扩展属于可选深入方向，入口见[职业分支](../tracks/career-labs.md)。

### 深入专题

[模块接口与设备适配](../topics/interfaces.md)：能力声明、观测、任务、超时与控制权。

## 验证方法

| 检查项 | 预期结果 | 提交证据 |
| --- | --- | --- |
| 环境 | 缺失条件可定位，基础电脑示例可运行 | 环境报告 |
| 通信 | 正常、超时和错误目标可区分 | 请求/回复记录 |
| 设备扩展 | 型号、接口、权限和状态来源可追溯 | 基线与只读日志 |

设备接入成功不等于已验证运动控制。
