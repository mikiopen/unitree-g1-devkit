# 决策

设备接入 → 感知 → 决策 → 执行 → 反馈 → 部署维护

## 能力目标

根据用户意图、感知结果和设备状态选择任务，并管理执行过程。覆盖文本路由、技能选择、状态机/行为树、任务分解、导航规划、多机任务分配、超时与恢复。

大模型可提供候选意图或计划，执行前仍需校验目标、参数、权限与设备条件。

### 从意图到任务

| 子方向 | 需要决定什么 | 对外输出 |
| --- | --- | --- |
| 意图解析 | 用户在请求什么，目标是否明确？ | 候选任务或拒绝 |
| 前置检查 | 状态、权限、资源和能力是否满足？ | 接受/拒绝及原因 |
| 任务分解 | 哪些技能串行，哪些允许并行？ | 子任务与依赖 |
| 规划 | 目标如何满足环境和设备约束？ | 路径、步骤或不可行结果 |
| 异常处理 | 失败后停止、恢复还是转人工？ | 明确的后续状态 |

## 前置条件

需要[感知](02-perception.md)的观测、[反馈](05-feedback.md)的当前状态，以及设备声明支持的能力。入门使用固定文本和模拟条件即可。

## 输入输出与接口

| 边界 | 约定 |
| --- | --- |
| 输入 | 用户意图、当前状态、有效观测、设备能力与任务约束 |
| 输出 | 明确接受或拒绝的结果，以及包含目标和参数的任务计划 |
| 错误 | 未知意图、状态缺失、能力不支持、超时、取消和执行失败 |

已有白名单输出`accepted`、`command`、`mode`和`motion_executed`。任务ID、技能参数、行为树与规划器属于扩展设计，尚不是该脚本已实现的接口。

## 最小示例

1. 按[10文本路由](../tutorials/10-router.md)分别输入“查询状态”和“向前走”，观察允许与拒绝。
2. 按[04命令生命周期](../tutorials/04-control.md)设计准备、执行、结束、异常和取消状态。
3. 在纸面流程中加入状态过期、目标失联和执行失败，说明何时终止，何时可以重试。

白名单脚本只输出dry-run计划，不调用机器人。

## 可修改与扩展点

替换意图识别器、实现技能注册、状态机或行为树、加入导航路径规划与多机调度。运动与抓取规划需使用对应模型、约束和碰撞信息。

重试是否会重复动作、取消何时生效、失败后是否允许恢复，都由任务接口明确约定，不能默认无限重试。

## 验证方法

| 检查项 | 预期结果 | 提交证据 |
| --- | --- | --- |
| 允许与拒绝 | 未知或不满足条件的任务不进入执行 | 正反例输出 |
| 生命周期 | 取消、超时和失败有明确去向 | 状态图与场景记录 |
| 规划扩展 | 计划遵守能力与环境约束 | 规划结果及约束检查 |

本仓库已有精确白名单与生命周期设计任务，未提供通用任务执行器、导航规划器或大模型自主控制系统。
