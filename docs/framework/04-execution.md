# 执行

设备接入 → 感知 → 决策 → 执行 → 反馈 → 部署维护

## 能力目标

把任务计划转换为设备支持的动作。覆盖厂商高层运动接口、关节与轨迹控制、手臂/灵巧手操作、抓取、音频播放、轨迹跟踪和结束处理。

调用厂商行走接口与自行开发平衡、步态、全身控制是不同深度；后者作为控制算法扩展。

### 执行路线选择

| 子方向 | 框架关注点 | 使用者需补齐 |
| --- | --- | --- |
| 高层运动接口 | 请求、模式与反馈 | 厂商接口适配 |
| 动作与轨迹 | 数据、单位、时间和限值 | 关节映射及跟踪 |
| 手臂与灵巧手 | 目标、规划、接触与结果 | 型号配置和操作策略 |
| 音频与其他外设 | 队列、开始、完成与中断 | 后端驱动和资源 |
| 控制算法 | 状态、周期、约束与模型 | 算法、仿真与设备验证 |

## 前置条件

设备能力、接口契约与控制权限明确。真实动作还需型号、关节映射、单位、限值、当前状态、动作资源和经过验证的结束方法。电脑上的结构校验不具备这些全部条件。

## 输入输出与接口

| 边界 | 约定 |
| --- | --- |
| 输入 | 任务目标、动作/轨迹/播放参数、设备标识与执行约束 |
| 输出 | 接受结果、执行进度、完成/失败结果与取消反馈 |
| 错误 | 参数越界、控制权冲突、资源缺失、接口失败和反馈超时 |

区分“已发消息”“接口接受”“实际完成”。取消请求与设备确认结束是两个事件；不同设备采用各自支持的停止方式。

## 最小示例

1. 按[05动作数据](../tutorials/05-action-data.md)校验教学CSV与阶段JSON，理解维度、时间和单位。
2. 按[11广播契约](../tutorials/11-broadcast.md)设计队列、播放与中断接口。
3. 在仓库根目录执行 `python g1.py demo` 观察模拟命令与回复，不驱动机器人。
4. 设备扩展按[04验收设计](../tutorials/04-control.md)完成状态、控制权、单命令与结束验证。

## 可修改与扩展点

开发者可实现厂商 SDK 适配、动作编排、路径跟踪、机械臂运动规划、抓取与触觉闭环、音频播放适配。先用[动作数据教程](../tutorials/05-action-data.md)和[任务编排专题](../topics/tasks.md)定义自己的接口与验收用例。

运动算法、模仿学习和强化学习放在可选算法路线中；仿真通过后仍需验证模型误差、延迟、限制与设备适配。

## 验证方法

| 检查项 | 预期结果 | 提交证据 |
| --- | --- | --- |
| 数据 | 正常数据通过，异常维度/时间/数值被拒绝 | 校验报告 |
| 模拟 | 请求和响应对应，明确未执行运动 | 模拟报告 |
| 设备扩展 | 状态、动作、结束及异常处理分别有证据 | 单命令与停止记录 |

现有动作JSON只做结构检查；广播为契约设计；机器人运动、抓取和音频播放没有因文档整理而获得实机验证。
