# 反馈

设备接入 → 感知 → 决策 → 执行 → 反馈 → 部署维护

## 能力目标

让系统和使用者知道设备正在做什么、结果是否有效、失败发生在哪里。覆盖状态订阅、日志与指标、故障码、在线诊断、Web/App/平板界面、操作进度与取消反馈。

反馈返回决策形成闭环，也为部署维护提供诊断依据。

### 三类反馈服务三种使用者

| 反馈对象 | 需要的信息 | 避免的问题 |
| --- | --- | --- |
| 决策模块 | 状态有效性、任务进度、执行结果 | 以旧状态触发下一任务 |
| 操作人员 | 当前目标、进度、失败与可用操作 | 把未知展示为成功 |
| 维护人员 | 模块日志、时延、错误与资源状态 | 无法关联一次任务的故障 |

为每项状态说明来源、更新时间与失效规则。面板刷新频率不等于设备采样频率。

## 前置条件

需要数据来源、请求标识、时间与失效规则。电脑实验使用模拟状态和回环回复；读取真实设备需满足[设备接入](01-access.md)的条件。

## 输入输出与接口

| 边界 | 约定 |
| --- | --- |
| 输入 | 设备遥测、执行事件、通信结果、故障与日志 |
| 输出 | 给决策层的有效状态、给使用者的进度和告警、给维护者的诊断证据 |
| 错误 | 状态过期、重复/乱序回复、请求不匹配、超时与目标筛选 |

仅收到回复不能证明动作完成；没有回复也可能来自筛选、丢包或超时。界面显示数据来源与可确认的状态，不把未知显示为成功。

## 最小示例

1. 按[03状态读取](../tutorials/03-state.md)获取`synthetic`数据，并说明字段和单位。
2. 按[07多设备诊断](../tutorials/07-fleet.md)观察群发、单目标、掉线与恢复。
3. 按[12界面](../tutorials/12-ui.md)显示通信状态；无桌面时用命令行输出完成同样的状态解释。
4. 将状态变化反馈到[04命令生命周期](../tutorials/04-control.md)的设计中。

## 可修改与扩展点

增加遥测字段、日志查询、可视化、故障码解释、Web/App客户端、多机状态面板和告警。遥操作须另外设计身份权限、控制权、断线处理与延迟反馈。

当前独立状态示例只展示有限字段；时间同步、连续状态估计和完整监控平台由开发者自行扩展。

## 验证方法

| 检查项 | 预期结果 | 提交证据 |
| --- | --- | --- |
| 来源 | 模拟、DDS和业务事件能够区分 | 标注来源的日志 |
| 通信 | 正常、目标过滤、无回复和恢复可解释 | 四组诊断记录 |
| 界面 | 未知/失败不显示为成功，状态与实际证据对应 | 交互记录 |

设备状态是运动前置条件，因此03章可在执行环节之前学习；六环节是职责划分，不是单向调用限制。
