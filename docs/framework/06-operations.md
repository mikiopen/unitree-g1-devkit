# 部署维护

设备接入 → 感知 → 决策 → 执行 → 反馈 → 部署维护

## 能力目标

将开发结果交付到目标环境，并持续检查运行情况。覆盖仿真与回放、测试与评估、依赖和配置、进程/服务管理、监控、打包、升级、回滚、权限和资源许可。

仿真、数据采集与算法评估贯穿整个开发过程，不必等到最后才开始。

### 从开发结果到运行交付

| 子方向 | 需要管理的内容 | 交付物 |
| --- | --- | --- |
| 验证 | 单模块、接口、场景与故障 | 测试及适用范围 |
| 资源 | 配置、模型、标定与数据 | 可追溯清单 |
| 启停 | 依赖顺序、健康检查与设备结束 | 启动/停止说明 |
| 运行 | 日志、指标、权限与告警 | 诊断入口 |
| 变更 | 升级、兼容性、失败与回退 | 演练方案与结果 |

## 前置条件

每个启用的能力都有接口、环境与验证范围。电脑路线可直接运行仓库回归；设备交付需额外提供固件/SDK/资源、运行日志、结束与恢复证据。

## 输入输出与接口

| 边界 | 约定 |
| --- | --- |
| 输入 | 源码、依赖、配置模板、设备基线、模型/数据与验收项 |
| 输出 | 可复现运行说明、测试报告、部署包、监控与回退步骤 |
| 错误 | 缺依赖、启动失败、设备断线、资源不匹配、升级失败与回退失败 |

固定软件和资源标识，区分配置错误与运行故障。模型来源、许可和数据隐私单独记录。

## 最小示例

1. 按[13项目交付](../tutorials/13-delivery.md)生成电脑模拟报告。
2. 执行 `python tools/verify_learning.py` 检查文档与电脑实验，再运行公开发布与隐私检查。
3. 运行 `python g1.py preflight` 列出设备准备缺口，默认缺设备信息时返回待补状态。
4. 让另一环境按说明复现，记录缺项与运行结果。

测试不会自动安装设备服务或发布OTA。

## 可修改与扩展点

可增加MuJoCo等仿真适配、数据录制与回放、标注与训练流水线、模型评估、容器/systemd、指标监控、OTA与回滚验证。具体平台与算法由使用者选择。

现有[控制仿真](../../examples/career-labs/README.md)是教学简化模型，不是 G1 全身仿真。固件与整机升级必须遵循厂商正式流程，并在独立环境完成回退验收。

## 验证方法

| 检查项 | 预期结果 | 提交证据 |
| --- | --- | --- |
| 复现 | 环境、配置和命令足以复现声明的能力 | README及测试报告 |
| 故障处理 | 启动失败、掉线、退出和恢复结果明确 | 故障记录 |
| 部署扩展 | 重启、升级、回滚符合项目约定 | 目标设备验收日志 |

已有电脑验证与构建证据见[验证资料](../README.md)。完成六环节文档不表示全部能力已有实现或通过实机验收。
