# 第 NN 章：章节名称

> 编写模板。能力指南与实践教程统一使用以下六个二级标题；主任务、条件扩展、常见问题与导航放在对应栏目内的三级标题下。

## 能力目标

说明本能力的职责、问题与最小成果。列出可以理解或完成的目标，不把待扩展能力写成已经实现。

## 前置条件

| 项目 | 内容 |
| --- | --- |
| 所属环节 | 与course.json一致：设备接入、感知、决策、执行、反馈或部署维护 |
| 学习类型 | 导读、电脑、设备、设计或条件实验，与章节元数据一致 |
| 必需环境 | 最小示例需要的系统、工具和设备 |
| 可选条件 | 扩展需要的模型、外设、服务；没有则写“无” |
| 前置章节 | 链接依赖的知识或示例，没有则写“无” |
| 接口依据 | 实际源码、协议、SDK、数据与配置；注明是否只是拟定契约 |
| 验证状态 | 区分设计、静态检查、电脑模拟、模型推理和设备实测，并链接证据 |

### 准备与配置

说明运行位置、依赖与资源。设备扩展记录型号、固件、SDK、网卡与控制权限，配置模板不写真实凭证。

## 输入输出与接口

| 边界 | 约定 |
| --- | --- |
| 输入 | 类型、来源、单位/坐标/时间和必要参数 |
| 输出 | 结果、状态、错误及关联标识 |
| 错误边界 | 超时、缺失、拒绝、取消等行为 |

说明输入→处理→输出，区分已实现接口与建议设计。跨环节依赖通过链接表达。

## 最小示例

### 主任务

1. 检查输入与环境。
2. 执行一个可复现的示例或设计任务。
3. 观察正常结果与一个失败/边界案例。
4. 正常结束，说明进程与设备状态。

### 条件扩展

没有扩展时省略此三级标题；有扩展时明确进入条件。程序退出不能代替设备停止验证。

## 可修改与扩展点

写明可替换的模块、配置和算法；每个扩展交代应保留的接口与验证要求。提供方向，由开发者自行实现适配；不要只写泛泛的“可以继续优化”。

## 验证方法

| 检查项 | 预期结果 | 提交证据 |
| --- | --- | --- |
| 正常路径 | 可对照的结果 | 日志、报告或设计文件 |
| 异常路径 | 明确拒绝、超时或恢复 | 失败记录 |
| 扩展适配 | 输入输出与既定接口一致 | 对照实验及适用范围 |

### 常见问题

按现象、检查顺序和处理方法说明。
