# 课程大纲与教学安排

课程对象：零基础或刚接触编程、希望通过G1案例认识工程开发的学习者。课程结构统一采用[六环节开发框架](learning-framework.md)，逐章操作统一采用[六栏目模板](lesson-template.md)。本页只规定准备内容、节奏与评价，不重复维护章节目录。

## 准备单元P1–P4

| 单元 | 先掌握什么 | 进入主线前的成果 |
| --- | --- | --- |
| P1 编程 | Python变量、函数、字典、文件、异常与模块 | 读写JSON，错误路径有说明 |
| P2 系统 | 路径、终端、进程、标准输出、虚拟环境 | 能从正确目录启动/结束程序 |
| P3 网络 | IP、子网、端口、TCP/UDP和客户端/服务端 | 解释端口与IP、ping与应用通信的区别 |
| P4 工程记录 | Git、README、配置、依赖与日志 | 提交可复现命令和一次排错 |

本仓库提供G1案例中的工程入门，不替代完整Python、Linux或电路基础教材。

## 教学节奏

每次围绕一个章节主任务：理解问题 → 操作或设计 → 制造边界情况 → 验收 → 复盘。建议按个人基础安排两次实践和一次复盘，不用固定周数承诺就业能力。按示例前置条件安排学习，设备执行前先完成只读状态与结束方法验证，章节与阶段成果见[学习框架](learning-framework.md)。

有设备/模型的学员和无设备学员共享电脑主线。条件扩展单独验收：型号、自由度、固件、SDK、网卡、资源、账号与停止方法没有证据时标为待补，不改变电脑主任务结论。

## 统一评价

| 维度 | 建议比例 | 看什么证据 |
| --- | --- | --- |
| 原理解释 | 20% | 输入输出、状态来源、关键边界 |
| 实现与复现 | 30% | 源码、环境、配置、他人复现 |
| 故障定位 | 25% | 一次失败、排查顺序与修正理由 |
| 交付与复盘 | 25% | 成果完整、本人贡献、限制与下一步 |

这是课程评价方案，不是招聘标准。只展示视频或“程序跑了”不足以通过，应能解释一处错误和一个设计取舍。

## 职业分支

共同主线后选择两条[职业体验](tracks/career-labs.md)，再确定主方向。MCU/RTOS需C与数字电路；BSP需C、Linux与体系结构；硬件需器件资料与仪器；控制需数学和力学；AI需数据与模型评估。具体任务和起步代码从分支页进入，不塞进每章主任务。

## 教师与维护者

章节按[模板](lesson-template.md)写，目录与类型登记到[course.json](../configs/course.json)。教程结构、链接与电脑代码通过检查后再提交；实际验证日期与范围写入证据页，不能通过改状态文案替代验证。维护步骤见[贡献说明](../CONTRIBUTING.md)。
