# 系统架构

## 总体闭环

```text
设备与环境
   ↓ 原始数据
设备接入 → 感知 → 决策 → 执行
   ↑                    ↓
部署维护 ← 日志与诊断 ← 反馈
```

六个环节通过明确的数据契约连接，而不是把厂商 SDK、算法和界面写进一个进程。

| 环节 | 典型输入 | 典型输出 | 必须处理的失败 |
| --- | --- | --- | --- |
| 设备接入 | 网卡、SDK、设备能力 | 统一状态与命令通道 | 版本不匹配、断连、权限不足 |
| 感知 | 相机、IMU、关节、音频 | 带时间戳和坐标系的观测 | 丢帧、过期、置信不足 |
| 决策 | 观测、目标、安全约束 | 可取消的任务或动作请求 | 无解、冲突、超时 |
| 执行 | 任务请求、轨迹或动作 | 接受、进行中、完成、拒绝 | 越界、急停、执行超时 |
| 反馈 | 设备状态与执行事件 | 面向人和系统的可解释状态 | 状态陈旧、语义不一致 |
| 部署维护 | 配置、版本、日志 | 可复现部署和回退证据 | 配置漂移、升级失败 |

## 分层建议

1. **领域层**：定义状态、任务、结果和错误码，不依赖厂商 SDK。
2. **适配层**：把领域接口映射到具体设备、DDS/ROS 2 或其他协议。
3. **安全层**：身份、白名单、限幅、超时、急停和状态确认。
4. **应用层**：界面、任务编排、数据记录和用户交互。
5. **运维层**：配置、进程守护、日志、指标、升级和回退。

仓库的 `g1devkit/` 与 `examples/` 主要覆盖领域层的教学实现；`adapters/reference/` 只展示适配层契约。真实设备适配需要使用与硬件和固件匹配的官方接口自行实现。

## 最小消息语义

每个跨进程请求至少包含：协议版本、请求 ID、目标设备、命令、参数、创建时间和截止时间。每个结果至少包含：请求 ID、设备 ID、状态、时间和错误说明。接收方必须能够拒绝未知版本、重复请求、过期请求和越权命令。

## 安全边界

自动测试只允许静态检查、本机文件、合成数据和回环网络。真实机器人动作必须单独启用，由现场人员确认环境、支撑、防护距离和急停有效性。
