# 职业体验实验：同一项目，不同工程工作

这些实验是供学习者和教师执行的任务书。现有电脑通信、数据与文本实验已提供源码；固件、驱动、硬件、控制算法和真机交付任务仍需要相应设备与实现。每个体验结束都填写 [作品复盘](../portfolio-template.md)。

## A. 嵌入式软件：MCU/RTOS

问题：外设不能直接运行整套机器人程序时，怎样稳定上报按键和传感器数据？

1. 先选择有公开原理图、官方 SDK 和调试支持的普通开发板，用 USB 串口接开发电脑。
2. 用 C 编写心跳计数与按键上报；先用串口终端观察，再写 Linux/Python 接收端。
3. 定义消息边界、序号和校验方式，记录串口参数；通过断线、截断消息验证接收端。
4. 将采样和通信分成两个任务，记录共享资源与调度；有 RTOS 的板卡再测任务运行时间。

交付：固件源码、构建说明、串口协议、波形或日志、资源与周期测量。必须能回答“为什么要中断”“为什么队列满了”“什么决定发送周期”。只编写 Python 接收端不能算完成固件体验。

## B. Linux 驱动/BSP

问题：应用无法读取某个开发板外设，应该从哪里定位？

1. 在普通开发板上记录启动日志、内核版本、设备树来源、设备节点和用户权限。
2. 选择一个官方已支持的 GPIO/I²C/UART 外设，从原理图引脚追到设备树，再到驱动与应用。
3. 在独立实验环境中改变一项配置，保存改变前后的设备日志，解释故障落在哪一层。
4. 用官方 BSP 流程完成一次构建，并记录源码版本和构建产物；能恢复原系统后再尝试修改。

交付：启动链图、外设匹配路径、编译步骤、定位报告。仅安装 Python 包或调用 SDK 不算驱动开发。第一轮不要在承载机器人服务的系统上做内核移植实验。

## C. 嵌入式硬件

问题：怎样设计一个能被 MCU 读取的低压按键/传感器接口板？

1. 以普通开发板为主控，写出输入电压、电流、逻辑电平、连接器和使用环境需求。
2. 查选定器件的数据手册，设计去耦、按键输入和连接器，逐项写明依据。
3. 用 EDA 画原理图与 PCB，记录 ERC/DRC；在打板前审阅极性、引脚、电源和测试点。
4. 在独立低压供电下测电压和信号，比较实测与设计；再连接开发板，最后才设计 Linux 接入。

交付：原理图、PCB 源文件、BOM、设计计算、测量记录、修订原因。此任务书没有规定机器人接口电气条件；不得据此直接接机器人内部电源或总线。硬件体验的成果首先是一块独立外设板。

## D. 嵌入式 Linux 应用

问题：两个设备中有一个掉线，服务如何准确报告结果？

运行 [06](../tutorials/06-udp.md)、[07](../tutorials/07-fleet.md)，加入时间戳与日志保存。把“请求已发送”“收到模拟回复”“真实操作完成”拆成不同状态。增加重复请求去重时，先定义请求 ID 保存时长与重启行为，再写验证案例。

交付：协议说明、运行程序、双端结果、掉线证据、设计取舍。继续深入可将接收端用 C++ 实现，并测并发、退出和内存使用；Python 实验属于路线入口。

## E. 机器人软件与系统集成

软件体验聚焦任务与状态：完成 03、05、10，画出状态 → 决策 → 命令 → 反馈的路径，明确 SDK 与业务逻辑边界。集成体验聚焦部署：完成 02、13 的设备扩展，固定设备和版本，记录服务顺序与故障定位。

交付：软件体验提供数据映射、命令契约与日志；集成体验提供设备矩阵、部署文档和验收报告。模拟反馈、源码阅读与机器人执行证据分别标记。

## F. App、前端与后端

先实现“设备列表、连接状态、状态查询、超时提示”四个交互，用 [12](../tutorials/12-ui.md) 对照现有 Flutter 代码。电脑模拟协议使用独立适配层，保留现有 App 的文本协议；两者不能直接混用。

前端方向记录页面状态和用户操作；后端方向记录 API、参数校验与错误响应；桌面/移动方向记录异步事件、连接生命周期与构建环境。认证和付费业务不作为第一轮体验前提。

交付：可运行入口或明确的界面设计、接口文档、错误路径、构建记录。使用现有界面时说明自己修改的部分。

## G. AI 应用

用自录的短句构建小测试集，在 [09](../tutorials/09-asr.md) 转写后，进入 [10](../tutorials/10-router.md) 的白名单。加入同音词、噪声、空音频与未知指令，分别统计识别正确率和命令接受情况。

交付：数据来源、模型版本与许可、期望文本、实际输出、误差分析、拒绝路径。模型能回答问题不代表控制命令可靠；第一轮结果停在模拟或日志。

## H. 控制算法

先在自己实现的简单单关节模型或适用的公开仿真模型中比较位置阶跃和插值轨迹，再比较参数变化对误差与振荡的影响。写明模型假设、时间步长、输入限制和评价指标。

交付：推导或假设、仿真代码、曲线、参数对比与局限。仿真中的参数不可直接复制为 G1 真机控制参数。此分支尚未提供完整机器人模型与训练框架。
