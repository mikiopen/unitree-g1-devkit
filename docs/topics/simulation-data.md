# 仿真、数据与学习算法

类型：扩展设计指南。提供接口与验证方向，具体实现由使用者完成。

## 能力目标

用分层验证减少一次性整机集成的不确定性：先测试接口逻辑，再测试模型与控制，最后验证真实设备。训练算法是可选路线，数据采集与回放也可服务普通工程排错。

## 前置条件

明确要验证的层次、目标设备模型、传感器与动作定义。采集数据时记录设备/资源标识、环境与任务结果；训练前准备独立评估样本。

## 输入输出与接口

| 层次 | 输入与输出 | 能证明什么 |
| --- | --- | --- |
| 逻辑模拟 | 固定事件 → 状态/错误/任务结果 | 接口与任务分支，不含真实动力学 |
| 数据回放 | 已记录观测 → 算法输出 | 给定数据上的可重复性，不保证在线时序 |
| 物理仿真 | 模型、场景、控制 → 仿真状态 | 所设模型条件下的行为 |
| 设备验证 | 真实传感器与控制 → 实际反馈 | 记录的设备和环境范围内的结果 |

宇树的`unitree_mujoco`提供SDK2相关仿真桥接，官方当前说明主要覆盖低层开发；仿真与实机的部分状态可用性并不相同。接入前核对所用提交、消息类型和模型。[官方仿真说明](https://github.com/unitreerobotics/unitree_mujoco)

### 一次数据采集至少记什么

会话/任务ID、设备与软件标识、标定、观测及时间、命令与实际反馈、成功/失败、人工接管或中断、资源来源。不要只保存成功演示；训练与评估数据按任务、场景或采集会话合理分离，避免相邻帧泄漏。

## 最小示例

1. 从[电脑demo](../tutorials/13-delivery.md)拿到报告，标明它属于逻辑模拟。
2. 阅读[控制仿真示例](../../examples/career-labs/README.md)，列出简化模型没有包含的整机特性。
3. 设计一份采集清单，将观测、命令、反馈和结果按任务关联；本页不新增采集器。
4. 选择一个失败场景，例如延迟反馈，在回放或模拟设计中复现，预先写出判定标准。

## 可修改与扩展点

可接MuJoCo或其他仿真器、实现数据录制/回放、加入视觉标注、遥操作示教、模仿学习和强化学习。观测归一化、动作缩放、控制频率、历史窗口与坐标定义需随模型保存。

仿真迁移时检查质量/惯量、接触、摩擦、延迟、噪声、饱和和外设差异。随机化可以用于覆盖模型不确定性，不能替代实机验收。没有与任务相关的评估指标时，先定义指标再训练。

## 验证方法

| 检查项 | 预期结果 | 提交证据 |
| --- | --- | --- |
| 可复现 | 数据、模型、代码与配置可定位 | 资源清单与运行说明 |
| 数据分离 | 评估样本未混入训练/调参流程 | 划分规则 |
| 失败覆盖 | 延迟、缺失、异常和中断有结果 | 分场景统计 |
| 迁移边界 | 仿真支持与设备支持差异明确 | 差异表与设备记录 |

现有简化控制仿真、文件ASR和回环demo属于不同验证层次，不统称为机器人仿真已通过。
