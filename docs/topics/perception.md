# 坐标、标定与视觉感知

类型：扩展设计指南。提供接口与验证方向，具体实现由使用者完成。

## 能力目标

把图像、深度和设备状态转成可解释的空间信息。开发顺序建议为读取数据 → 确认时间与坐标 → 标定 → 检测/估计 → 输出观测。

像素框、三维位置与可抓取姿态是不同结果，接口应明确输出属于哪一种。

## 前置条件

准备可离线读取的图像或传感器数据、对应内外参及数据来源。空间输出需要知道相机/雷达与机器人之间的变换；没有标定时可以先完成二维识别。

## 输入输出与接口

| 输入 | 输出 | 必须明确 |
| --- | --- | --- |
| 图像 | 像素框、类别、模型分数 | 分辨率、时间、模型和分数含义 |
| 深度与相机内参 | 相机坐标下的点 | 深度单位、无效值、深度定义及畸变处理 |
| 三维点与外参 | 机器人参考坐标下的点 | 变换方向、参考坐标与采样时刻 |
| 多源观测 | 位姿或状态估计 | 时间对齐、有效范围和失效条件 |

### 坐标与时间约定

采用ROS约定时，机体通常使用x向前、y向左、z向上；相机光学坐标通常为z向前、x向右、y向下。具体设备可能不同，适配层必须显式转换。[REP-103](https://raw.githubusercontent.com/ros-infrastructure/rep/master/rep-0103.rst)

移动平台中的`odom`强调连续性但允许漂移，`map`用于全局参考但定位修正可能产生跳变；不要将二者混作同一条连续控制轨迹。[REP-105](https://raw.githubusercontent.com/ros-infrastructure/rep/master/rep-0105.rst)

定义`T_base_camera`为“把相机坐标转换到机体坐标”的变换，则齐次点满足`p_base = T_base_camera × p_camera`。运动中的安装部件需要使用对应时刻的变换。

## 最小示例

1. 取一张有已知目标的图像，记录分辨率、来源与采集条件；没有时间信息就标未知。
2. 用人工标注或自行选择的检测器得到二维框，先画回图像确认像素坐标正确。
3. 纸面练习：设相机与机体轴向完全一致，仅相机原点位于机体`[0.2, 0, 1.0] m`处；相机中的点`[0.5, 0.1, 0.2] m`转换后为机体中的`[0.7, 0.1, 1.2] m`。这些是教学假设，不是G1安装参数。
4. 真实相机扩展需处理轴向旋转、内外参、时间同步与误差，再对照已知位置目标。

本仓库不附带视觉工程。学习者需要自行选择有明确许可证的驱动和算法，并按本页契约完成设备适配与独立验证。

## 可修改与扩展点

可实现目标检测、人体姿态、视觉跟踪、深度定位、手眼标定与多传感器融合。先定义下游需要“类别、位置还是完整位姿”，避免在尚无深度与标定时输出貌似精确的三维结果。

遮挡、空图、错误单位、坐标颠倒、旧帧和目标离开视野都应成为测试输入。模型分数不能直接当成已校准的正确概率。

## 验证方法

| 检查项 | 预期结果 | 提交证据 |
| --- | --- | --- |
| 像素定位 | 框与目标对齐，分辨率变化可解释 | 标注与可视化 |
| 坐标变换 | 已知点转换与对照值一致 | 坐标图及误差表 |
| 真实标定 | 用未参与拟合的样本检查误差 | 标定配置与验证样本 |
| 数据失效 | 遮挡、旧帧或缺标定时明确降级/拒绝 | 异常记录 |

误差阈值由相机、工作距离与任务精度确定，本框架不预设通用厘米级指标。
