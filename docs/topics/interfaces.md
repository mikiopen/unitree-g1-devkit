# 模块接口与设备适配

类型：扩展设计指南。提供接口与验证方向，具体实现由使用者完成。

## 能力目标

把设备、算法与任务拆成可替换模块。每个模块只承担明确职责，替换SDK或模型时，上层仍能理解成功、失败与数据含义。

本页给出项目设计约定，不提供已经实现的统一RPC、JSON协议或SDK。已有示例格式仍按各自源码使用。

## 前置条件

先读[六环节](../learning-framework.md)与[设备接入](../framework/01-access.md)。选择一种真实能力，例如读取状态；先核对厂商实际开放的接口，再定义应用侧适配。

## 输入输出与接口

| 边界 | 建议记录 | 不应混淆 |
| --- | --- | --- |
| 能力声明 | 设备标识、支持的操作、参数范围、控制模式与依赖 | 模块已安装与设备支持该能力 |
| 观测 | 来源、采集/接收时间、时钟域、单位、坐标系、有效性 | 采集时间与接收时间 |
| 任务请求 | 任务标识、目标设备、技能、参数、期限与权限上下文 | 请求标识与重复执行许可 |
| 执行事件 | 任务标识、状态、错误、进度、结果、设备会话 | 接口接受与动作完成 |
| 配置 | 环境与设备配置、资源标识、密钥引用 | 可分享模板与真实凭证 |

### 四个需要提前决定的语义

- **超时**：超时意味着调用者尚未确认结果，可能仍有任务在设备端运行；先查状态或取消，不直接重复运动。
- **重复请求**：同一标识是否返回已有结果、是否拒绝重复、保留多久，由执行模块定义。UDP本身不提供业务去重。
- **时间**：本机耗时可用单调时钟；跨机时间比较需说明同步方式与误差，不能直接相减两台机器的单调时间。
- **控制权**：明确当前持有者、移交条件与断线处理。连接成功不代表获得运动控制权。

## 最小示例

1. 为“读取状态”写一张接口卡：输入为设备ID，输出为带来源和时间的状态，错误包括无连接、不支持与超时。
2. 为“执行技能”另写接口卡，补充任务ID、参数校验、取消与结果查询。
3. 用纸面事件模拟请求已接受但回复丢失，说明调用方如何确认任务是否已执行。
4. 对照[06UDP](../tutorials/06-udp.md)与[13组合示例](../tutorials/13-delivery.md)，列出两者实际字段，不能将本页建议字段直接发送给它们。

```text
设计接口示意（非可调用API）
读取能力 → 检查参数与状态 → 提交任务 → 接收反馈 → 查询最终结果
                                      ↘ 请求取消 → 等待结束确认
```

## 可修改与扩展点

设备适配可封装SDK/DDS/ROS 2/串口/CAN；上层任务只使用能力接口。为测试提供模拟适配，为硬件提供设备适配，明确两者支持的能力差异。

订阅状态、短时查询和长任务可采用不同通信机制。若使用ROS 2，Actions提供长任务反馈与取消的机制，可作为任务接口的参考；不意味着本仓库已接入Actions。[ROS 2 Actions](https://raw.githubusercontent.com/ros2/ros2_documentation/jazzy/source/Concepts/Basic/About-Actions.rst)

## 验证方法

| 检查项 | 预期结果 | 提交证据 |
| --- | --- | --- |
| 可替换性 | 更换模拟/设备适配后，上层可识别支持范围与错误 | 两份接口卡及差异表 |
| 重复与超时 | 不因回复丢失而无条件重复执行 | 事件时序与恢复说明 |
| 参数与控制权 | 无效参数、错误目标与无控制权明确拒绝 | 正常及拒绝案例 |
| 结果语义 | 接受、执行和完成分别可追溯 | 关联任务的事件记录 |
