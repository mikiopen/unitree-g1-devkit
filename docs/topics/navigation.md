# 建图、定位与导航

类型：扩展设计指南。提供接口与验证方向，具体实现由使用者完成。

## 能力目标

将“去某个位置”拆为定位、环境表示、路径规划、运动跟踪和到达判断。先实现单个目标点，再扩展巡检路线、多点任务与动态环境。

## 前置条件

已有可用里程计/定位与传感器数据、机器人占用空间描述、运动接口和结束方式。纯电脑阶段可以只做离线地图与路径设计，不能据此认定G1能沿路径行走。

## 输入输出与接口

| 模块 | 输入 | 输出与错误 |
| --- | --- | --- |
| 建图/定位 | 传感器、里程计、标定及地图 | 地图/位姿；标明定位丢失或不可用 |
| 路径规划 | 当前位姿、目标、地图与约束 | 可行路径或无法规划 |
| 跟踪与局部避障 | 路径、局部障碍和运动状态 | 运动请求或无法继续 |
| 到达判断 | 实际位姿、目标与任务容差 | 完成、未到达、取消或失败 |

Nav2将定位、环境表示、规划、控制与行为协调拆成可组合能力，可用于理解模块边界。[Nav2导航概念](https://docs.nav2.org/rolling/getting_started/navigation_concepts/)

对人形机器人，还需核对运动接口、姿态/步态条件、身体占用空间、地形与可行运动约束。二维地图上的空白区域不自动等于可行走地形；不要把轮式底盘参数直接套给G1。

## 最小示例

1. 在纸上画一个带障碍的网格，标起点、目标与机器人占用范围，规划一条无碰撞路线。
2. 在同一地图加入窄通道，解释点机器人可通过与有体积机器人可通过的区别。
3. 为定位丢失、目标不可达、障碍封路和中途取消画状态转移。
4. 有仿真条件时自行接入定位与控制适配，记录规划结果和实际轨迹；有设备后按相同验收项逐步验证。

本仓库没有现成G1导航栈；[07多设备实验](../tutorials/07-fleet.md)只覆盖通信和失联诊断。

## 可修改与扩展点

可替换SLAM、定位器、全局规划、局部跟踪器与障碍表示；多机扩展增加任务分配、占用协调和通信故障处理。

跟随人还需要目标身份与目标丢失策略；巡检还需要到点作业与结果记录。导航恢复动作由实际设备能力与场地条件决定，不默认执行倒退、旋转等动作。

## 验证方法

| 检查项 | 预期结果 | 提交证据 |
| --- | --- | --- |
| 定位 | 位姿来源和失效条件明确 | 位姿/地图与对照日志 |
| 路径 | 满足占用空间与环境约束 | 路径及约束说明 |
| 到达 | 根据实际状态确认，不能仅看命令返回 | 目标与最终位姿 |
| 故障 | 丢定位、不可达、封路、取消有明确结果 | 四类场景记录 |

容差、速度、地形与恢复策略由项目定义，需与设备能力匹配。
