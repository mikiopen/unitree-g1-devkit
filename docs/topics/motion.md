# 运动、手臂与抓取扩展

类型：扩展设计指南。提供接口与验证方向，具体实现由使用者完成。

## 能力目标

按项目深度选择厂商运动接口、动作轨迹、机械臂/灵巧手操作或控制算法开发。每条路线都从设备支持范围和状态反馈开始，不通过目录名推断接口。

## 前置条件

设备型号、自由度、控制模式、固件/SDK、模型和关节映射已确认。抓取还需要工具几何、目标位姿、标定与接触反馈；低层控制需进一步明确控制周期、状态估计与限值。

## 输入输出与接口

| 路线 | 输入与输出 | 自行实现部分 |
| --- | --- | --- |
| 厂商高层运动 | 设备支持的目标/速度请求 → 实际运动状态 | 模式、参数、控制权与结束适配 |
| 动作/轨迹 | 关节目标与时间 → 跟踪状态 | 关节顺序、单位、约束、插值与反馈 |
| 手臂规划 | 目标位姿与场景 → 可执行轨迹 | 机器人/工具模型、碰撞场景和控制器适配 |
| 灵巧手与抓取 | 抓取目标/手势 → 关节及接触结果 | 型号接口、抓取判据、滑移/失败处理 |
| 全身控制 | 任务与估计状态 → 多执行器控制 | 动力学、平衡、接触、实时性与验证 |

MoveIt运动规划可根据机器人模型、约束和碰撞场景生成轨迹；它的规划结果仍需要对应控制器执行与反馈。引用该架构不代表本仓库已有G1 MoveIt适配。[MoveIt运动规划](https://moveit.picknik.ai/main/doc/concepts/motion_planning.html)

## 最小示例

1. 运行[05数据校验](../tutorials/05-action-data.md)，区分结构合法、映射正确与运动可行。
2. 选择一份设备接口资料，列出关节名称、顺序、单位和支持的控制方式，未知项留空待核对。
3. 纸面拆解抓取：确认目标 → 获得位姿 → 规划接近 → 执行 → 闭合 → 确认持有 → 后续任务。
4. 为“闭合完成但没有抓到物体”补充结果判据，说明位置、力、触觉或视觉证据各能证明什么。

纸面与离线练习不发送运动指令；实机按照[执行环节](../framework/04-execution.md)完成独立验收。

## 可修改与扩展点

可替换轨迹生成器、逆运动学、抓取候选生成、碰撞检查、手部适配与反馈判据。双臂协作需要额外检查空间冲突、持物约束与协调关系。

模仿/强化学习可用于某些控制或操作模块，必须保持训练与部署的观测/动作定义一致；路线见[仿真与数据](simulation-data.md)。

## 验证方法

| 检查项 | 预期结果 | 提交证据 |
| --- | --- | --- |
| 映射 | 名称、顺序、单位、左右侧一一对应 | 映射表及来源 |
| 规划 | 约束与碰撞检查在声明模型下成立 | 场景、规划配置与结果 |
| 跟踪 | 实际状态与目标差异可评估 | 轨迹与反馈记录 |
| 抓取 | 成功条件不只等于手已闭合 | 持有/失败对照案例 |
| 结束 | 正常、取消与异常均有设备状态证据 | 结束记录 |

本页不给通用增益、速度、力矩或手部动作映射；这些参数必须来自对应设备及实验条件。
