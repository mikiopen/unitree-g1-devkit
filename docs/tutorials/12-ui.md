# 第 12 章：界面与通信状态

> 环节 E · 反馈。本章成果：基础交互记录与错误状态表。

## 能力目标

运行电脑模拟界面，观察目标选择、状态查询、回声和结束四项交互。

- 把用户操作对应到请求和结果。
- 明确显示模拟、等待、成功、失败与数据过期。
- 区分界面原型和真实设备应用。

## 输入输出与接口

用户选择目标 → 事件回调 → 教学通信服务 → 模拟回复 → 界面更新。界面必须展示数据来源和更新时间；发送请求不等于设备完成动作。

| 边界 | 约定 |
| --- | --- |
| 输入 | 目标选择、用户事件和带请求 ID 的模拟回复 |
| 输出 | 等待、结果、错误、来源和更新时间 |
| 错误边界 | 无回复、非法目标、过期数据和部分失败不能显示为成功 |

## 最小示例

1. 在仓库根目录启动：

   ```bash
   python g1.py gui
   ```

2. 选择 `all` 查询状态，再选择单个模拟设备发送回声，对照回复中的设备 ID 和模拟标记。
3. 点击结束模拟，再查询状态，应保持 `idle`。
4. 关闭窗口，确认程序创建的模拟线程和套接字退出。
5. 为“无设备、等待、超时、数据过期、部分成功”各设计一条界面反馈。

无桌面环境时运行 `python g1.py demo` 验证通信链路，并完成界面状态设计。

## 可修改与扩展点

可以替换成 Web、移动端或桌面框架，但应保持请求关联、时间信息、数据来源和未知状态可见。真实设备界面还需要控制权、权限、断线和急停状态，不能只显示一个“已连接”标志。

## 验证方法

| 检查项 | 预期结果 | 提交证据 |
| --- | --- | --- |
| 基础交互 | 选择、查询、回声和结束的结果可解释 | 四项交互记录 |
| 状态来源 | 能分清已发送、模拟回复与设备确认 | 页面状态表 |
| 错误反馈 | 等待、超时、离线和过期不显示为成功 | 状态截图或设计图 |
| 生命周期 | 关闭界面后教学线程和端口释放 | 退出记录 |

### 常见问题

| 现象 | 检查与处理 |
| --- | --- |
| Tkinter 不可用 | 检查 Python 是否包含 Tk 和桌面环境；改跑 `g1.py demo` |
| 点击后一直等待 | 检查模拟端是否启动、请求 ID 是否匹配以及超时是否可见 |
| 旧状态看起来像实时 | 同时显示采样时间、接收时间和过期标记 |
