# 第 09 章：语音文件转写

> 环节B · 感知。本章成果：转写结果和误差记录。

## 能力目标

把一段自己可使用的语音WAV转为文字，记录识别误差；条件不足时先列清依赖，不虚构转写结果。

- 区分音频解码、模型加载与文本输出。
- 记录模型版本、输入格式和误差。
- 让识别文本先经过10章白名单。

### 准备与配置

在独立 Python 环境安装可选依赖。模型来源、许可、文件哈希与放置规则见[资源说明](../resources.md)。使用自行录制并同意用于测试的语音；08章纯音不能作为语音验收素材。Windows 模型加载失败时优先在英文目录复核。

## 输入输出与接口

WAV解码 → Vosk按块推理 → 分段/最终text。转写示例不采集麦克风、不访问在线服务、不发动作；g1.py voice只把精确允许的文本送到本机模拟端。

| 边界 | 约定 |
| --- | --- |
| 输入 | 兼容WAV与指定本地模型路径 |
| 输出 | 识别文本与运行结果 |
| 错误边界 | 缺模型、格式不匹配、加载失败与识别错误分别记录 |

## 最小示例

1. 在仓库根目录、所选Python环境安装依赖：

   ```text
   python -m pip install -r examples/09-asr-demo/requirements.txt
   ```

2. 将模型解压、语音WAV准备完成，先用08章inspect核对文件属性。用实际路径替换下列示例：

   ```text
   python examples/09-asr-demo/transcribe_file.py .local/hello.wav --model .local/vosk-model
   ```

3. 记录text，比较预期与实际。模型/包缺失或WAV不合格式时，应明确失败，不继续进入动作。
4. 完成10章后，可用同一音频验证文件到模拟端的完整链路：

   ```text
   python g1.py voice --audio .local/hello.wav --model .local/vosk-model
   ```

5. 文件结束后程序退出；Ctrl+C可中断。模型和录音保留本地，不进入Git。

## 可修改与扩展点

替换模型或增加流式输入时保留文本输出边界，记录延迟与识别误差；不要将识别器直接接到运动发布接口。

### 实践成果

准备10条短句，保留安静/噪声条件和整句正确比例，不隐去空识别。交付转写与误差记录；条件不足则交依赖缺项单。对应工作：模型部署、数据评估与AI应用。

## 验证方法

| 检查项 | 预期结果 | 提交证据 |
| --- | --- | --- |
| 转写 | 正确环境中得到text；空识别也如实记录 | 模型信息与转写JSON |
| 误差 | 记录预期文本、实际文本、噪声和错误类型 | 短句评估表 |
| 模拟串接 | 允许句进入白名单并收到模拟回复，motion_executed=false | 条件齐备后的链路报告 |

### 常见问题

| 现象 | 检查与处理 |
| --- | --- |
| 模型加载失败 | 检查是否真正解压、文件是否齐全、语言/包/架构与路径；Windows复核英文路径。 |
| 空文本或识别不准 | 确认包含讲话，再核对音量、采样率、声道、噪声与模型语言。 |
| 电脑可运行而板端失败 | 检查目标架构、动态库、内存和模型兼容，保存错误信息。 |
