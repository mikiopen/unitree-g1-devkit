# 第 11 章：广播与桥接的消息契约

> 环节 D · 执行。本章成果：消息、队列与中断契约。

## 能力目标

为“一条指令驱动一个或多个输出服务”设计清晰的消息契约，而不绑定具体中间件。

- 区分接收、解析、排队、执行和中断职责。
- 定义单目标、广播、完成、失败与取消语义。
- 为队列、并发和资源释放制定验收项。

## 输入输出与接口

```text
请求入口 → 鉴权/校验 → 目标选择 → 队列 → 执行器 → 结果事件
                              ↑           ↓
                              └── 取消/超时 ┘
```

请求至少包含协议版本、请求 ID、目标、命令、参数、创建时间和截止时间；结果至少包含请求 ID、实际设备、状态、时间和错误原因。取消当前任务与清空等待队列必须是不同操作。

| 边界 | 约定 |
| --- | --- |
| 输入 | 带请求 ID、目标和截止时间的任务请求 |
| 输出 | 每个实际目标的接受、进行中、完成、拒绝或取消事件 |
| 错误边界 | 未知版本、重复、过期、离线和越权请求必须显式拒绝 |

## 最小示例

1. 设计 `submit`、`cancel`、`status` 三类消息，并给出有效与无效样例。
2. 画出“空闲 → 排队 → 执行 → 完成”的状态图，补充拒绝、超时、取消和执行失败。
3. 分别评审单目标、全部目标、重复请求、目标离线和执行中取消。
4. 规定请求 ID 的去重时长、服务重启后的行为和结果保留时间。
5. 列出线程、子进程、网络连接和设备句柄的释放顺序。

## 可修改与扩展点

可以把 UDP 替换为 ROS 2、DDS、消息队列或本地 IPC，但消息语义和验收场景应保持稳定。新增执行器时，通过适配层映射结果，不让上层依赖设备私有错误码。

## 验证方法

| 检查项 | 预期结果 | 提交证据 |
| --- | --- | --- |
| 消息契约 | 正常、拒绝、取消和超时可区分 | 请求/结果样例 |
| 广播语义 | 每台设备分别产生结果，不以发送成功代替执行完成 | 时序图 |
| 中断语义 | 当前任务、等待队列和后续请求边界明确 | 状态图 |
| 资源释放 | 正常退出与异常退出都有处理 | 清理清单 |

### 常见问题

| 现象 | 检查与处理 |
| --- | --- |
| 广播只返回一个成功 | 按实际目标分别聚合结果，并展示部分失败 |
| 重试导致重复执行 | 使用请求 ID、幂等策略和明确的去重窗口 |
| 取消后无法继续 | 检查队列状态、线程生命周期和设备资源释放 |
| 收到消息却没有输出 | 沿校验、路由、排队、执行和反馈逐层定位 |
