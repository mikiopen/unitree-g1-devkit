# 第 13 章：完成可复现的项目交付

> 环节F · 部署维护。本章成果：源码、配置、报告和作品复盘。

## 能力目标

把电脑主线交付为别人可以复现的项目，保存一次成功、一次失败和一份个人复盘。

- 按环境、配置、输入输出和证据组织交付。
- 运行完整模拟链路并保存报告。
- 把设备验收与电脑验证分开记录。

## 前置条件

| 项目 | 内容 |
| --- | --- |
| 所属环节 | 部署维护 |
| 学习类型 | 电脑实验，含设备扩展 |
| 必需环境 | Python3.10+和已完成的电脑主线；不依赖机器人、模型或后台。 |
| 可选条件 | 文件ASR需09章条件；设备交付需02/03/04的真实基线与日志。 |

| 接口依据 | 完整电脑链路用[g1devkit/runtime.py](../../g1devkit/runtime.py)、协议g1devkit/mock/v1；设备交付另固定完整配套。 |
| 验证状态 | 电脑组合、预检与回归测试由自动检查覆盖；真机完整交付未验证。见[验证说明](../validation.md)。 |

### 准备与配置

从仓库根目录运行。报告写.local/reports且拒绝覆盖，复现时选新的文件名。个人配置不提交，作品使用[复盘模板](../portfolio-template.md)。

## 输入输出与接口

环境与配置 → 输入 → 校验/路由 → 双设备模拟回复 → 报告 → 验收与复盘。独立章节的g1-learning/v1保留为拆解实验，完整维护入口使用g1devkit/mock/v1并自动管理生命周期。

| 边界 | 约定 |
| --- | --- |
| 输入 | 源码、环境、配置、测试与设备准备信息 |
| 输出 | 可复现运行说明、报告与缺项清单 |
| 错误边界 | 报告拒绝覆盖；预检待补不等于设备可运行 |

## 最小示例

### 主任务

1. 确认环境，运行完整模拟并保存证据：

   ```text
   python g1.py doctor
   python g1.py demo --report .local/reports/lesson13-demo.json
   ```

2. 对照报告中的群发状态、单目标回声、stop_demo和结束后再次查状态。说明目标过滤造成的未匹配端点不等于断电。
3. 运行离线预检，默认设备信息缺失时返回1并列出待补项：

   ```text
   python g1.py preflight --actions-dir adapters/reference/actions
   ```

4. 在07章保留一次掉线/恢复证据，再执行课程和来源检查：

   ```text
   python tools/check_course.py
   python tools/verify_learning.py
   python tools/check_publication.py
   ```

5. 将命令、环境、配置说明、报告、一次排错和本人贡献交给另一位学习者复现。demo结束自动清理线程和socket，无需手动结束模拟服务。

### 条件扩展：设备交付

固定型号/固件/SDK/网卡与App/订阅/动作/数据配套，按网络→状态→单命令/停止→群控→音频/语音→广播→UI逐层实测。记录依赖、资源、日志、重启、掉线与回退；本课程不自动安装systemd或发布OTA。

## 可修改与扩展点

增加目标设备部署、监控或升级适配，分别验证启动、重启、失败恢复与回滚；发布操作不纳入默认电脑测试。

### 实践成果

选[职业分支](../tracks/career-labs.md)中的两个方向，各规划一个小交付，再决定下一阶段主方向。交付完整作品包，包含源码、复现说明、成功/失败证据和局限。对应工作：软件工程交付、系统测试与工程复盘。

## 验证方法

| 检查项 | 预期结果 | 提交证据 |
| --- | --- | --- |
| 完整模拟 | passed=true、motion_executed=false，停止后状态保持idle | 一份新建运行报告 |
| 失败解释 | 有掉线/恢复证据，能解释预检blocked与目标过滤 | 失败记录和待补单 |
| 可复现 | 另一个人能按说明运行，局限与本人贡献明确 | README、配置说明、复盘 |

### 常见问题

| 现象 | 检查与处理 |
| --- | --- |
| 报告文件已存在 | 改用新文件名，保留先前证据；不要默认覆盖。 |
| preflight返回1 | 阅读blocked具体缺项，静态待补不是程序崩溃。 |
| 电脑通过但设备不工作 | 补设备基线和逐层日志，不能把模拟通过当作设备支持。 |
| GitHub同步失败 | 检查目标仓库、当前账号权限和认证状态，避免把本地验证成功误认为远端同步成功。 |
