# 第 05 章：动作数据结构与校验

> 环节D · 执行。本章成果：正常与异常数据校验报告。

## 能力目标

检查教学CSV及现有动作JSON，区分数据结构通过与真实动作可执行。

- 校验表头、时间、列数和有限数值。
- 明确动作文件的布局与单位。
- 保留原文件并记录一份错误案例。

## 前置条件

| 项目 | 内容 |
| --- | --- |
| 所属环节 | 执行 |
| 学习类型 | 电脑实验 |
| 必需环境 | Python3.10+和仓库中的教学数据；无需机器人。 |
| 可选条件 | 已有动作JSON可做静态检查；DOF必须明确指定为格式契约。 |

| 验证状态 | CSV 与动作 JSON 静态检查由自动测试覆盖；没有验证真实轨迹。见[验证说明](../validation.md)。 |

### 准备与配置

从仓库根目录运行。需要修改数据时复制到.local，保留教材原件。数值审阅阈值由调用者提供，不能当作所有机器人关节的物理限位。

## 输入输出与接口

读取文件 → 检查结构与数值 → 输出报告，不修复文件、不导入SDK。toy.csv的time_s/q0_rad/q1_rad是两个虚构关节，不能当作G1关节映射。

| 边界 | 约定 |
| --- | --- |
| 输入 | 教学CSV或选定格式的动作JSON与维度参数 |
| 输出 | 结构校验结果及数据统计 |
| 错误边界 | 非有限数、非法时间与维度不符应拒绝；通过不代表运动适配 |

## 最小示例

1. 检查教学CSV：

   ```text
   python examples/05-action-data/inspect_csv.py examples/05-action-data/toy.csv --joints 2 --max-abs-rad 1
   ```

2. 在.local副本中制造重复时间、NaN或缺列，用同一工具逐项检查，记录拒绝原因。
3. 检查一个已有阶段JSON；29表示本次审阅的布局，不代表识别了你的机器人：

   ```text
   python g1.py inspect-action adapters/reference/actions/init.json --dof 29
   ```

4. 对照输出的阶段数、时长、输入宽度、SHA-256与转换计数。若审阅23自由度布局，明确改为--dof 23。
5. 工具读完即退出，不写动作文件、不发送运动。

## 可修改与扩展点

新增数据格式解析器或字段校验，保持单位、关节顺序和时间语义明确；设备限值来自实际资料，不从示例阈值推断。

### 实践成果

为一个旧数据文件写格式说明，列出时间、单位、映射和执行器版本。交付正常/错误报告及适配说明。对应工作：数据接口与机器人动作数据工程。

## 验证方法

| 检查项 | 预期结果 | 提交证据 |
| --- | --- | --- |
| CSV正常 | rows=3、joints=2、duration_s=0.2、schema_valid=true | 原始报告 |
| CSV异常 | 重复时间/NaN/缺列被拒绝，返回1 | 一份副本和错误报告 |
| JSON边界 | data含时长+11或17目标；motion_validated=false | JSON检查报告及布局说明 |

### 常见问题

| 现象 | 检查与处理 |
| --- | --- |
| 历史CSV被拒绝 | 先核对表头、时间列、单位和映射，写显式适配器，不自动猜列。 |
| JSON无法通过 | 检查顶层阶段列表、12/18宽度、正数时长和有限数值。 |
| 检查通过但不敢执行 | 还需逐关节映射、速度/力矩、初始姿态、碰撞与停止验证。 |
