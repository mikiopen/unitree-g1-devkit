# 第 02 章：网络、SSH与文件传输

> 环节A · 设备接入。本章成果：脱敏网络拓扑和连接记录。

## 能力目标

为自己的G1建立可核验的网络、SSH和测试文件传输记录；没有设备时先完成拓扑设计。

- 区分链路、IP路由、SSH认证和应用通信。
- 识别电脑网卡与机器人DDS网卡。
- 使用测试文件验证传输，不覆盖设备程序。

### 准备与配置

把个人网络记录放在.local，使用[设备基线](../../configs/device-baseline.example.json)。IP、掩码、用户名和网卡来自自己的设备资料；下面尖括号必须替换后再执行。

## 输入输出与接口

有线链路 → IP/路由 → SSH会话 → 测试文件。ping成功不证明DDS或UDP服务可用；Wi-Fi地址和DDS接口也不能混为一项。

| 边界 | 约定 |
| --- | --- |
| 输入 | 设备IP、网卡、认证方式与设备基线 |
| 输出 | 连通、SSH和文件传输的独立验证记录 |
| 错误边界 | 网络连通不代表SDK或应用服务可用 |

## 最小示例

1. 记录两端接口与掩码，为专用直连网卡设置同子网、不重复的地址；保留其他上网接口配置与恢复记录。
2. 在Windows检查实际接口和路由：

   ```powershell
   Get-NetIPConfiguration
   Get-NetRoute -AddressFamily IPv4
   ```

3. 核对到设备的路由后测试连通与登录；首次SSH连接核对主机身份：

   ```text
   ping <robot-ip>
   ssh <username>@<robot-ip>
   ```

4. 在机器人Linux会话中只读检查：

   ```bash
   ip -brief address
   ip route
   uname -a
   ```

5. 在开发电脑用自建测试文本验证SCP，远端使用新的测试文件名：

   ```text
   scp <local-test-file> <username>@<robot-ip>:~/g1-learning-test.txt
   ```

6. 确认远端测试内容，用exit结束SSH；按记录恢复临时电脑网络配置。改Wi-Fi前确认目标网络管理服务与恢复方法，保留有线入口。

## 可修改与扩展点

根据网络环境调整连接方式与文件传输流程，保留设备标识、认证和验证步骤；真实地址及凭证留在本地。

### 实践成果

画出电脑同时连接Wi-Fi与机器人有线网络的路由。交付脱敏拓扑和连接记录；没有设备时只交设计，标记未实测。对应工作：系统集成与现场网络排障。

## 验证方法

| 检查项 | 预期结果 | 提交证据 |
| --- | --- | --- |
| 连接记录 | 两端地址、掩码、路由和接口明确 | 脱敏拓扑与检查输出 |
| SSH与文件 | 能登录并确认测试文件内容 | 连接及传输记录 |
| 下一层条件 | 明确03章DDS所用Linux接口 | 基线中的网卡字段 |

### 常见问题

| 现象 | 检查与处理 |
| --- | --- |
| ping不通 | 检查上电/链路、地址掩码、路由和防火墙；部分系统禁用ping。 |
| SSH认证失败 | 核对自己的账号权限和认证方式，不猜默认密码。 |
| SSH正常但DDS无数据 | 下一章核对SDK、组播、网卡、域和话题。 |
