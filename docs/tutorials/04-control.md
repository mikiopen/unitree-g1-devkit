# 第 04 章：控制命令的生命周期

> 环节C · 决策。本章成果：命令状态机和单命令验收单。

## 能力目标

设计一次命令从允许、执行到结束的生命周期，并写清每种结果需要什么证据。

- 区分发送、SDK返回和实际动作完成。
- 设计缺状态、超时与取消路径。
- 分别确认进程退出与机器人停止。

## 前置条件

| 项目 | 内容 |
| --- | --- |
| 所属环节 | 决策 |
| 学习类型 | 设计练习，含设备扩展 |
| 必需环境 | 电脑、03章字段认识；主任务为设计，不启动运动。 |
| 可选条件 | 实机扩展需完成02/03、确定控制接口和已验证停止方法。 |
| 前置章节 | [03 状态](03-state.md)。 |
| 接口依据 | 主任务采用[教学路由器](../../examples/10-command-router/route_text.py)；真实命令须记录所选SDK、服务与数据版本。 |
| 验证状态 | 设计练习可在电脑完成；单命令真机执行待基线与现场验证。 |

### 准备与配置

用[作品模板](../portfolio-template.md)记录设计。真实适配器可能初始化控制模式、线程和命令发布，不应作为第一条运动实验。

## 输入输出与接口

准备检查 → 读取状态 → 允许/拒绝 → 调用接口 → 观察反馈 → 结束处理 → 确认结果。任意一步缺信息都应记录原因，不自动开始下一动作。

| 边界 | 约定 |
| --- | --- |
| 输入 | 命令、当前状态、能力与控制权条件 |
| 输出 | 允许/拒绝、执行、结束和异常的状态设计 |
| 错误边界 | 缺状态、超时与取消必须有去向 |

## 最小示例

### 主任务

1. 画出未准备、准备完成、执行中、结束处理中、完成/异常五种状态。
2. 为每种状态填输入、允许的操作、结束条件和日志；没有状态时应拒绝。
3. 使用电脑白名单观察允许与拒绝，不调用运动接口：

   ```text
   python examples/10-command-router/route_text.py "查询状态"
   python examples/10-command-router/route_text.py "向前走"
   ```

4. 给正常结束、中途取消、状态超时各走一遍纸面流程。程序打印后结束，无后台服务。

### 条件扩展：单命令验收设计

1. 完成02/03实测，记录当前模式、控制权和匹配官方接口。
2. 选一个短时、可观察的操作，审阅前置模式、返回值和停止/结束方法。
3. 在现场条件与看护齐备后才执行，分别保留发送、SDK与实际反馈。
4. 验证正常结束和取消。零力矩、阻尼、Ctrl+C各有效果，不能统称通用急停。

## 可修改与扩展点

实现自己的状态机或技能接口，明确任务标识、取消结果和重试条件；先以模拟执行器验证，设备控制另行适配。

### 实践成果

为“状态过期时收到命令”写一条拒绝说明。交付状态图和单命令验收单。对应工作：机器人任务层、控制生命周期与系统测试。

## 验证方法

| 检查项 | 预期结果 | 提交证据 |
| --- | --- | --- |
| 状态覆盖 | 正常、缺状态、超时、取消都有去向 | 命令状态图 |
| 电脑边界 | 查询允许、向前走拒绝，motion_executed=false | 两份路由输出 |
| 设备证据 | 实机结果和停止方法分别记录，未测则标未验证 | 单命令验收单 |

### 常见问题

| 现象 | 检查与处理 |
| --- | --- |
| 消息到达但没有动作 | 先核对格式、动作编号、模式、控制权和执行日志。 |
| 退出后行为不符预期 | 按已验证的现场结束流程处理；进程退出不是停止证据。 |
| 同一编号含义不同 | 检查动作服务、数据和设备配套，不混用版本编号。 |
